# 09 词库数据源调研报告

> 调研日期：2026-07-25 · 状态：✅ 已完成，结论已采纳
> 对应路线图：[M1 数据地基](./05-roadmap.md) 第一项（标记为 🔴 最大未验证风险）

## 结论速览

**风险解除。** ECDICT 自带 `ielts` 考试标签，直接提供 5,040 个雅思词，MIT 许可 —— 版权问题一并消失，不再需要从受版权保护的出版物提取词表。

音频和音标从 dictionaryapi.dev 获取，缺口用 edge-tts 和清洗版 ECDICT 兜底，最终 **100% 有音频、100% 有音标**。

唯一仍需自建的是**雅思话题标签**（用于阅读模式干扰项），任何现成数据源都没有这个字段。

## 1. 词表与释义：ECDICT

**来源**：[skywind3000/ECDICT](https://github.com/skywind3000/ECDICT) · **许可**：MIT · **规模**：770,611 词条

### 1.1 关键发现：自带考试标签

ECDICT 的 `tag` 字段标注了词条属于哪些考试大纲。实测全库标签分布：

| 标签 | 含义 | 词条数 |
|------|------|--------|
| `gre` | GRE | 7,504 |
| `toefl` | 托福 | 6,974 |
| `cet6` | 六级 | 5,407 |
| **`ielts`** | **雅思** | **5,040** |
| `ky` | 考研 | 4,801 |
| `cet4` | 四级 | 3,849 |
| `gk` | 高考 | 3,677 |
| `zk` | 中考 | 1,603 |

**这直接替代了对《刘洪波雅思词汇真经》的需求** —— 不必从受版权保护的出版物提取词表。

### 1.2 ielts 子集（5,040 词）字段完整度

| 字段 | 完整度 | 可用性 |
|------|--------|--------|
| `word` | 100% | ✅ |
| `translation` 中文释义 | 100% | ✅ |
| `definition` 英文释义 | 99.6% | ✅ 备用 |
| `phonetic` 音标 | 95.1% | ⚠️ 非标准记法，见 §3 |
| `bnc` / `frq` 词频 | 100% | ✅ 用于难度分级 |
| `collins` 星级 | 85.0% | ✅ 备用难度信号 |
| `exchange` 词形变化 | 84.5% | 暂不使用 |
| `pos` 词性 | **0%** | ❌ 字段全空，但可从释义前缀解析（见下） |
| `audio` 音频 | **0%** | ❌ 字段全空 |
| `detail` 例句 | **0%** | ❌ 字段全空 |
| **话题分类** | **字段不存在** | ❌ 必须自建 |

### 1.3 词性可从释义前缀解析

`pos` 字段虽空，但 `translation` 以词性缩写开头，**99.5% 可解析**：

```
abbreviation  →  "n. 缩写词, 缩写, 缩短, 节略"           →  n.
abnormal      →  "a. 反常的, 不规则的, 变态的, 畸形的"    →  a.
abolish       →  "vt. 废止, 革除, 消灭"                  →  vt.
```

前缀分布：`n.`(3399) `a.`(874) `vt.`(473) `vi.`(103) `v.`(83) `adv.`(49) `pl.`(11) `prep.`(9) `abbr.`(6) `num.`(3)

### 1.4 一词多义：75.1%

多义项在 `translation` 里用**字面 `\n`**（反斜杠+n 两个字符，非真换行）分隔。

| 指标 | 值 |
|------|-----|
| 含多义项的词 | 3,783 / 5,040（75.1%） |
| 平均义项数 | 2.06 |
| 最多义项数 | 6 |

**长度对比**（决定阅读模式选项如何呈现）：

| | 中位数 | 最长 | 超 40 字占比 |
|---|---|---|---|
| 完整释义 | 27 字 | 169 字 | — |
| 仅第一义项 | **14 字** | 83 字 | **1.6%** |

示例：

```
abstract
  完整: a. 抽象的, 深奥的 ／ n. 摘要, 抽象概念 ／ vt. 摘要, 提炼, 使抽象化 ／ [计] 摘录; 摘要; 抽象   (61 字)
  首义: a. 抽象的, 深奥的                                                                        (11 字)
```

第一义项确实是主要词义，且长度均匀 —— 适合做 4 选 1 的选项。完整释义太长且长度差异大，**长选项本身会泄露答案**。

## 2. 音频：dictionaryapi.dev + edge-tts

### 2.1 实测结果

**[dictionaryapi.dev](https://dictionaryapi.dev/)** —— 免费、无需 API key

| 指标 | 实测值 | 样本 |
|------|--------|------|
| 词条命中率 | 96% | 25 词随机抽样 |
| **有音频比例** | **70–76%** | 两轮抽样 |
| 音频托管主机 | `api.dictionaryapi.dev`（100%） | 20 词抽样 |
| 下载延迟中位数 | **760 ms** | 最慢 938 ms |
| 单词音频大小 | ~23 KB | accommodate 实测 |

缺音频的词包含常见词：`cafeteria` `classify` `underground` `audible` `charity` `technician`

**760ms 延迟意味着热链不可用** —— 听写时点"播放"要等近 1 秒，体验不可接受。且音频 100% 来自单一免费社区服务，热链既慢又是单点故障，还会骚扰对方。

**[edge-tts](https://github.com/rany2/edge-tts)** —— 实测可用

```
en-GB-SoniaNeural  →  10,656 bytes  ✅
en-US-AriaNeural   →  11,088 bytes  ✅
```

### 2.2 采纳方案

```
76% → dictionaryapi.dev 真人发音，seed 阶段下载到本地
24% → edge-tts 合成，seed 阶段生成到本地
────────────────────────────────────────────
100% 覆盖，全部本地文件，播放零延迟
```

预估存储：5,040 × ~20 KB ≈ **100 MB**（不进 git）

### 2.3 许可状况（诚实记录）

| 来源 | 许可状况 |
|------|---------|
| dictionaryapi.dev 音频 | 免费社区服务，无明确再分发许可。本地缓存自用风险低 |
| edge-tts | 库本身 LGPL-3.0；但微软那个 TTS 端点**没有公开的开发者协议**，缓存/再分发法律地位模糊 |
| Wikimedia Commons | CC 许可，唯一可安全再分发，但覆盖率低（未详测） |

**结论**：MVP 本地自用风险可接受。**v2 公网部署前必须复核** —— 届时若判定不可行，可退回浏览器 `SpeechSynthesis` 实时合成（改动量：一个字段判空 + 前端降级分支）。

## 3. 音标：改用 dictionaryapi.dev

### 3.1 ECDICT 音标的问题

**问题一：混入西里尔字母**

| 字符 | Unicode | 出现次数 | 说明 |
|------|---------|---------|------|
| `ә` | U+04D9 | 3,201 | **CYRILLIC SMALL LETTER SCHWA** —— 应为 IPA `ə` (U+0259) |
| `є` | U+0454 | 57 | **CYRILLIC SMALL LETTER UKRAINIAN IE** —— 应为 IPA `ɛ` (U+025B) |

影响 **2,490 / 5,040（49.4%）** 词条。其余符号（`ɒ æ ʃ ʌ ʒ ŋ ɑ θ` 等）都是合法 IPA。

**问题二：整套记音体系不是现代 IPA**

尝试用规则规范化后，与标准 IPA 对照 **0/8 一致**：

| 词 | ECDICT | 规则转换后 | 标准 IPA | |
|---|---|---|---|---|
| ability | `ә'biliti` | `/əˈbiliti/` | `/əˈbɪlɪti/` | ❌ |
| accommodate | `ә'kɒmәdeit` | `/əˈkɒmədeit/` | `/əˈkɒmədeɪt/` | ❌ |
| environment | `in'vairәnmәnt` | `/inˈvairənmənt/` | `/ɪnˈvaɪrənmənt/` | ❌ |
| photograph | `'fәutәgrɑ:f` | `/ˈfəutəgrɑːf/` | `/ˈfəʊtəɡrɑːf/` | ❌ |

系统性差异：

| ECDICT | 标准 IPA |
|--------|---------|
| `i` | `ɪ` |
| `ei` | `eɪ` |
| `ai` | `aɪ` |
| `әu` | `əʊ` |
| `ɒ:` | `ɔː` |
| `g` | `ɡ` (U+0261) |

**关键障碍**：单个 `i` 无法从字符判断该是 `ɪ` 还是 `i` —— 取决于具体单词，规则替换做不到。**"完全规范化成标准 IPA"这条路走不通。**

### 3.2 采纳方案：从 dictionaryapi.dev 取

实测 **96% 覆盖，返回真正的标准 IPA**：

| 词 | dictionaryapi.dev | ECDICT |
|---|---|---|
| thoughtful | `/ˈθɔːtfəl/` | `'θɒ:tful` |
| representative | `/ˌɹɛpɹɪˈzɛnt(ət)ɪv/` | `.repri'zentәtiv` |
| upright | `/ˈʌpɹaɪt/` | `'ʌprait` |

**零额外成本** —— seed 阶段本来就要为每个词调这个 API 拿音频，音标顺手取。

**两点处理**：
- API 用 `ɹ` (U+0279 turned r)，归一化为 `r`（学习者更熟悉）
- 缺失的 4% 用清洗版 ECDICT 兜底：`ә→ə` `є→ɛ` `'→ˈ` `.→ˌ` `:→ː`
  （`.` 经比对确认是**次重音标记**：`.æbә'ridʒәnәl` → `/ˌæbəˈrɪdʒənəl/`）

## 4. 话题标签：必须自建

**没有任何现成数据源提供雅思话题分类。**

- ECDICT 无此字段
- GitHub 搜索 "ielts vocabulary topic category" → **0 个结果**

这是阅读模式干扰项质量的命根子（见 [ADR-003](./08-decisions.md)），只能用 LLM 批量打标，并抽样人工校验。

---

## 5. 选词策略

**决定：5,040 词全部导入，并存下考试标签。**

5,040 个 ielts 词与其他考试大纲的重叠：

| 标签 | 重叠数 | 占比 |
|------|--------|------|
| cet6 六级 | 3,042 | 60.4% |
| ky 考研 | 3,058 | 60.7% |
| toefl 托福 | 2,911 | 57.8% |
| cet4 四级 | 2,146 | 42.6% |
| gre GRE | 2,114 | 41.9% |
| gk 高考 | 1,713 | 34.0% |
| zk 中考 | 641 | 12.7% |

排除中考/高考/四级后剩 2,316 词。

**为什么全导入**：
1. 导入不做取舍，"练哪些"变成应用层的筛选器（可选"跳过四级词"）—— 更灵活且零成本
2. Leitner 会自动把简单词推进 Box 5 不再出现，不浪费练习时间
3. 换筛选条件不用重跑 seed

**为什么不按词频取前 4000**：BNC 词频前列是 `in` `on` `say` `as` `get` —— 雅思考生不需要背这些。纯频率排序会让最没价值的词排最前，同时挤掉真正该学的难词。

## 6. 采纳的 seed 流程

```
0. 两趟扫描 ecdict.csv                          →  5,040 条 ielts 词
   ├─ 第一趟收集全部词形（判断屈折原型是否在表内需要全集）
   └─ 第二趟剔除 272 个冗余屈折形式             →  4,768 条
1. 解析词性（translation 前缀）                 →  99.5%
2. 拆分完整释义 / 首义                          →  100%
3. 音标先填清洗版 ECDICT 作为兜底
4. 逐词调 dictionaryapi.dev                     →  IPA 96% + 音频 76%
   ├─ 下载音频 MP3 到本地
   └─ 提取 IPA，ɹ→r，**删掉音节分隔点**
5. 无音频的用 edge-tts 生成                     →  音频补至 ~100%
6. LLM 批量打雅思话题标签 → 抽样人工校验         →  自建
```

### 6.1 屈折形式剔除（实测数据）

ECDICT 的 ielts 词表混入了屈折形式（复数、动名词等）：

| 类别 | 数量 | 处理 |
|------|------|------|
| 屈折形式且**原型也在词表里** | **272** | ❌ 剔除 —— `accommodations` 和 `accommodation` 同时存在，背两次无额外价值；且屈折形式在 API 里查不到，音标音频都缺 |
| 屈折形式但原型不在词表里 | 156 | ✅ 保留 —— 剔了就是纯丢词 |
| 专有名词（`Africa` `April` `AIDS`） | 66 | ✅ 保留 —— 雅思听力填空的真考点 |
| 短语（`account for` `bring about`） | 2 | ✅ 保留 —— 有用的短语动词 |

**最终词库规模：4,768 词**

识别方式：ECDICT 的 `exchange` 字段中 `0:xxx` 表示"本词是 xxx 的变形"。

### 6.2 音标里的 `.` 是个陷阱 ⚠️

**同一个字符在两个数据源里含义完全不同，绝不能用同一套规则处理：**

| 来源 | `.` 的含义 | 处理 |
|------|-----------|------|
| ECDICT 记音 | **次重音** | → `ˌ`（对照 `abbreviation` 的标准 IPA 反推确认） |
| dictionaryapi.dev 的 IPA | **音节分隔** | → 直接删掉 |

删音节点的理由：实测 45% 的 API 音标带音节点、55% 不带，格式不统一；且出现过 `/əˈ.bɪl.ɪ.ti/` 这种重音符紧跟音节点的瑕疵。学习者看音标关心读音和重音，音节边界是噪音。

这条差异已被 `tests/test_ecdict.py::test_dot_means_different_things_in_each_source` 钉住，防止将来有人"统一"这两个函数。

### 6.3 断点续跑设计

**不用单独的状态文件**，拿 `words.audio_source` 当状态机 —— 重跑即续跑：

| `audio_source` | 含义 | 谁处理 |
|---|---|---|
| `NULL` | 还没调过 API，**或上次调用失败** | 阶段 2（会重试） |
| `pending-tts` | 调过了，但该词 API 没音频 | 阶段 3 |
| `dictapi` | 已有真人发音 ✓ | 完成 |
| `edge-tts` | 已有 TTS 音频 ✓ | 完成 |

阶段 1 靠 `(word_list_id, word)` 唯一约束 + `ON CONFLICT DO NOTHING` 幂等。

**关键性质**：调用失败时**不写** `audio_source`（保持 NULL），所以失败的词不会被静默跳过，重跑自动重试。已实测验证 —— 40 词试跑中 `abrasion` 失败一次，重跑时精确地只处理了它。

**已知成本**：
- 第 4 步约 **20–26 分钟**（4,768 词，并发 4；比原估的 75 分钟快，因为并发）
- 音频约 **100 MB**（不进 git）

**工程要求**（已实现）：
- ✅ 断点续跑（`audio_source` 状态机）
- ✅ 限速（并发 4 + 每请求延迟 0.1s + `User-Agent` 标明用途）
- ✅ 失败重试（指数退避 3 次，429 单独处理）
- ✅ 分批落库（每 100 词提交一次，中断不丢已完成的）
- ✅ 高频词优先（`ORDER BY frq`，中断了也先有常用词）

## 7. 全量导入实测结果（2026-07-25）

调研的预测与实际跑完的结果对照 —— **预测相当准确**：

| 指标 | 调研预测 | 实际结果 |
|------|---------|---------|
| 词库规模 | 5,040 → 剔冗余 → 4,768 | **4,768** ✅ |
| 真人音频（dictapi） | 76% | **75.6%**（3,606） |
| TTS 补齐（edge-tts） | 24% | **24.4%**（1,162） |
| 音频总覆盖 | 100% | **100%**（4,768 个文件，84.7 MB） |
| 音标覆盖 | ~96% | **99.2%**（4,732） |
| 阶段 2 耗时 | 20–26 分钟 | **38.8 分钟**（含 154 次失败重试） |

### 7.1 数据完整性校验

```
每条记录的音频文件都存在        缺失 0
空释义                          0
无音标                          36  （0.8%，屈折形式和短语，ECDICT 与 API 都没有）
无词性                          19  （0.4%，释义以领域标记 [经]/[计] 开头）
无考试标签                      0
音标里的西里尔字母残留          0    ← 清洗生效
```

难度分布（从 `exam_tags` 推导）：

| 难度 | 词数 | 占比 |
|------|------|------|
| 1（含中考/高考/四级） | 2,704 | 56.7% |
| 2（含六级/考研/托福） | 1,505 | 31.6% |
| 3（仅雅思/GRE） | 559 | 11.7% |

### 7.2 一个值得记住的现象：失败集中在开跑瞬间

首轮跑完有 **154 个失败**（3.2%），全是 `might` `American` `director` `record` `position` 这类**高频常用词**。

原因是 seed 按 `ORDER BY frq NULLS LAST` 排序（高频词优先，中断了也先有常用词），所以这些词在**开跑最初几秒**被处理 —— 那时 4 个并发连接同时冲上去，没有任何预热。

补跑一轮（`--concurrency 2 --delay 0.4`）后 **154 个全部成功、0 失败**。

**这恰好验证了断点续跑的价值**：失败保持 `audio_source IS NULL`，不会被静默跳过，重跑自动重试。如果当初把失败标记成 `failed` 状态，这 154 个高频词就会永久缺音频，而且不会有任何提示。

**给后来者的建议**：首轮用默认并发（快），跑完看 `--status` 若有残留就用 `--concurrency 2 --delay 0.4` 补一轮。
